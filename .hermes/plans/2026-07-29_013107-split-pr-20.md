## Risks and tradeoffs

- Rewriting PR #20 changes its head history. Exact `--force-with-lease` plus the backup ref prevents silent data loss.
- Splitting produces more PR overhead, but gives clear review ownership and independent rollback.
- NIO-only is not a documentation-only technical change. Database/RPC enforcement needs a later, high-risk migration plan after product approval.
- Trello write tokens can alter external project state. Dry-run is insufficient by itself; a disposable board is the safest real-path test.
- The Trello skill currently embeds a private board URL/ID and user-specific credential-file assumptions. Decide deliberately whether those belong in a shared repository.
- Cherry-picked commit IDs change. PR descriptions should refer to behavior/files, not depend on the original SHA remaining in branch history.
